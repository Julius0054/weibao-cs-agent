# 示例住宅项目 · 维保智能客服 Agent（云小维）

基于 **CodeBuddy Agent SDK** 构建的房屋维保智能客服系统，面向某开发商·示例住宅项目 A 地块业主报修与咨询场景。

> 前台：业主自助报修 / 政策咨询 · 后台：对话记录 / 满意度 / 工单 / 转人工 / 知识库运营

---

## 一、能力清单

| 能力 | 实现方式 |
| --- | --- |
| 多轮对话 | SSE 流式输出，SDK Session `resume` 保持上下文，历史全量落库 |
| FAQ 知识库检索 | 中文 bigram 重叠度 + 关键词加权，Top-K 命中注入提示词，前端可展开查看引用 |
| 意图识别 | 规则加权 + 实体抽取（房号 / 手机号 / 工单号），8 类意图，越界问题自动收敛 |
| 职责边界 | 系统提示词严格框定「房修报修 + 常见问题」，与维保无关的问题礼貌拒答并引导 |
| 自动派单 | 复用 A 地块责任划分规则，按「楼栋 + 问题描述」判定 **责任单位 / 工种**，生成工单号 `BXYYYYMMDDNNN` |
| 转人工留言 | 模型自报 `need_human` + 规则兜底（多轮未解决 / 投诉 / 越界 / 低分评价），弹窗收集联系方式 |
| 对话持久化 | SQLite（WAL），会话 / 消息 / 工单 / 转人工 / 满意度 五张业务表 |
| 管理后台 | 数据概览、对话记录回溯、工单流转、转人工闭环、知识库增删改 + 检索测试 |
| 离线兜底 | SDK 不可用时自动降级为本地知识库应答，界面标注「本地知识库」 |

## 二、快速开始

### 方式一：一键启动（推荐，日常使用）

直接双击项目根目录的 **`启动.bat`**（或 `dev-node22.cmd`），脚本会自动完成：

1. 定位 WorkBuddy 自带的 Node 22 运行时（解决 `better-sqlite3` 原生模块 ABI 兼容问题）；
2. 若 `dist/` 缺失则自动 `vite build`；
3. 启动 Express —— **同一端口同时托管 API 与已打包的前端**（默认 `3000`，被占用则自动顺延 `3001`/`3002`…）；
4. 自动打开浏览器。

启动后访问：

- `/`　　　智能客服（业主侧）　→　http://localhost:3000/
- `/admin`　管理后台（维保中心侧）　→　http://localhost:3000/admin

> 服务仅绑定 `127.0.0.1`（本机），关闭启动器窗口即整体退出，不留残余进程。

首次进入后台可点击 **「填充演示数据」** 生成 10 组真实场景会话，概览页统计立即可见。

### 方式二：开发模式（改代码用，带热更新）

```bash
npm install          # 安装依赖
npm run dev          # 后端(3000) + Vite 前端(5173, 热更新)
```

前端开发地址 http://localhost:5173（API 经 Vite 代理到 3000）。生产形态请用方式一。

### 环境变量

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `PORT` | 服务端口（启动器会自动顺延到空闲端口） | `3000` |
| `CODEBUDDY_API_KEY` | CodeBuddy SDK 凭据；**不设置则自动走本地知识库兜底（离线模式）** | 未设置 |
| `CODEBUDDY_INTERNET_ENVIRONMENT` | 中国区填 `internal` | `internal` |
| `CB_MODEL` | 默认模型（账号仅支持中文模型，勿用 `claude-sonnet-4`） | `deepseek-v4-pro` |
| `DEMO_OFFLINE` | 置 `1` 强制走本地知识库（无需 SDK 登录） | 未设置 |

```bash
# 离线演示（无需 SDK 凭据）
DEMO_OFFLINE=1 npm run dev

# 指定端口启动（一键启动器）
PORT=8080 node start-app.js
```

## 四、对话链路

```
业主提问
  → 意图识别（规则加权 + 实体抽取）
  → FAQ 检索 Top3（命中计数 +1）
  → 用户消息落库
  → SSE init：推送意图标签 / 知识库命中 / 派单建议
  → Agent SDK 流式应答（剥离 <<<META>>> 结构化块）
  → 解析 META：ticket / need_human / resolved / missing
  → 要素齐全 → 自动生成工单（含责任单位与工种）
  → 需人工 → 创建转人工记录并推送卡片
  → 助手消息落库（意图 / 引用 / 耗时 / 是否需人工）
  → SSE done
```

**META 协议**：模型在回答末尾附加一段机器可读 JSON，前端不可见，后端据此执行派单与转人工，避免依赖工具调用。
